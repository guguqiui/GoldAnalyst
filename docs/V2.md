# Gold Analyst V2 设计

## 目标

V1 证明了单个调查员可以完成“模型选择工具 → Python 执行 → 结果回传 → 报告审核”的闭环。

V2 要解决两个问题：

1. 同一个说法只由一个调查员研究，容易受单一路径影响。
2. 三种研究策略目前由用户手工选择，系统不会根据结果改进策略。

V2 第一版将三个策略研究员并行运行，再由独立裁判合并；随后用可复现的任务集评价策略，并进行选择和变异。

## 完整流程

```text
用户问题
  ├─ 来源优先研究员 ─┐
  ├─ 口径优先研究员 ─┼─> 裁判：去重证据、比较冲突、合并报告
  └─ 反证优先研究员 ─┘
                              ↓
                      确定性验证 + 人工可读报告
                              ↓
                    保存本轮策略、成本与评分
                              ↓
                 选择较好策略，产生下一代变体
```

## 多智能体边界

- 每个研究员拥有独立消息历史、工具预算和证据空间，避免互相污染。
- 研究员之间不讨论，也不直接复制对方结论。
- 裁判只接收候选报告和已经取得的证据，不允许重新解释网页中的指令。
- `submit_report` 仍由确定性代码检查引用编号。
- V1 保持可用；V2 是显式选择的模式，避免自动产生三倍 API 费用。

## 策略基因

第一阶段只使用容易理解和约束的字段：

| 字段 | 示例 | 作用 |
|---|---|---|
| `strategy` | `source_first` | 研究顺序与提示词 |
| `rounds` | 3–6 | 最多模型轮数 |
| `tool_calls` | 6–12 | 研究工具总预算 |
| `parallel_tools` | 1–4 | 单轮并行工具数 |
| `counter_check` | 0/1 | 是否强制检查反面解释 |

V2 的第一项代码改动是 `ResearchBudget`，把 V1 写死的预算变成可配置对象。

## 适应度

不能仅按“证据多”评分，否则策略会通过重复搜索刷分。适应度由四部分组成：

1. **硬约束**：引用存在、算术正确、报告结构合法。
2. **证据质量**：原始来源占比、来源独立性、日期和合约口径完整度。
3. **任务质量**：在固定评测任务上，结论是否符合已知答案或人工标注。
4. **成本**：Token、搜索次数、工具次数和耗时。

`证据不足` 不直接扣分；在证据确实不足时诚实保留，比编造确定结论得分更高。

## 迭代顺序

### V2.1 多策略竞争

- 同时运行三个有独立预算的研究员。
- 为证据编号增加候选前缀，避免三个 `E1` 冲突。
- 裁判合并重复来源并输出最终报告。
- 页面展示每个候选的结论、成本和裁判取舍。

### V2.2 评测

- 建立少量可复现的黄金事实核验任务。
- 加入确定性评分器和盲审裁判。
- 保存每次运行的策略参数与分项得分。

### V2.3 进化

- 从表现较好的策略中选择父代。
- 对提示顺序和预算做有限变异。
- 在相同评测任务上比较父代与子代。
- 只有分数稳定提高时才替换默认策略。

## V2.1 验收标准

- 一个问题能够产生三个互相独立的候选报告。
- 三个候选可以并行运行，并分别受预算约束。
- 相同来源不会在最终报告中冒充多个独立证据。
- 裁判必须说明采用或拒绝每个候选核心结论的原因。
- 任一候选失败时，其他候选仍能完成。
- V1 原有测试和单调查模式继续通过。
